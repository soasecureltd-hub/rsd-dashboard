# Deploying RSD

| Part | Host | Config |
|---|---|---|
| Frontend (React/Vite) | Vercel | `frontend/vercel.json` |
| Backend (FastAPI, Docker) | Render | `render.yaml`, `Dockerfile.backend` |
| Database | Supabase Postgres | `DATABASE_URL` |

Order matters: **database → backend → frontend → connect them**, because each
step needs a URL from the one before.

---

## 1. Supabase (database)

1. Create a new project at supabase.com. Save the database password somewhere safe.
2. Open **Connect** → **Session pooler** and copy the URI. It looks like:
   ```
   postgresql://postgres.<project-ref>:[YOUR-PASSWORD]@aws-0-<region>.pooler.supabase.com:5432/postgres
   ```
   Use the **session pooler**, not the "Direct connection": the direct host is
   IPv6-only and Render can't reach it.
3. Put your password in, **URL-encoding** special characters
   (`@` → `%40`, `$` → `%24`, `#` → `%23`, `/` → `%2F`), and append
   `?sslmode=require`. This full string is your `DATABASE_URL`.

You don't create tables: the backend runs the Alembic migrations on every start.

## 2. Render (backend)

1. render.com → **New** → **Blueprint** → connect the GitHub repo. Render reads
   `render.yaml` and proposes the `rsd-backend` service.
2. Fill in the variables it asks for:
   - `DATABASE_URL`: the Supabase string from step 1
   - `ALLOWED_ORIGINS`: leave as `http://localhost:5173` for now (fixed in step 4)
   - `ALLOWED_ORIGIN_REGEX`, `SENTRY_DSN`: optional, can stay empty
   - `JWT_SECRET_KEY` is generated by Render automatically.
3. Deploy. In the logs you should see the migrations run
   (`Running upgrade -> 001 … 003`) and then uvicorn start.
4. Check `https://<your-service>.onrender.com/health` returns `{"status":"healthy"}`.
   Note the base URL: the API is at `https://<your-service>.onrender.com/api`.

Free Render services sleep when idle; the first request after a pause can take
~30-60 s. The first threat prediction also trains the model (a few seconds).

## 3. Vercel (frontend)

1. vercel.com → **Add New… → Project** → import the GitHub repo.
2. **Root Directory: `frontend`** (important; the repo root is not the app).
   Framework preset: Vite (picked up from `vercel.json`).
3. **Environment Variables** → add for Production *and* Preview:
   - `VITE_API_URL` = `https://<your-service>.onrender.com/api`

   It's baked in at build time, so changing it later needs a redeploy.
4. Deploy and note the production URL, e.g. `https://rsd-frontend.vercel.app`.

## 4. Connect them (CORS)

Back in Render → `rsd-backend` → **Environment**:

- `ALLOWED_ORIGINS` = your Vercel production URL, exactly, no trailing slash
  (e.g. `https://rsd-frontend.vercel.app`). Add a custom domain here too,
  comma-separated, if you add one later.
- Optional, so Vercel preview deployments work too:
  `ALLOWED_ORIGIN_REGEX` = `^https://rsd-frontend(-[a-z0-9-]+)?\.vercel\.app$`
  (replace `rsd-frontend` with your Vercel project name).

Save; Render redeploys the backend.

## 5. Smoke test

1. Open the Vercel URL, register, log in.
2. Run an assessment, open AI Predictions, try a What-If scenario.
3. Download the PDF report; check History.

If the browser console shows a **CORS error**, `ALLOWED_ORIGINS` doesn't match
the page's origin exactly. If requests go to `localhost:8000`, `VITE_API_URL`
wasn't set for that deployment: set it and redeploy.

## Secrets checklist

- Never commit `.env`, the Supabase password or `DATABASE_URL`.
- `JWT_SECRET_KEY` is generated by Render; changing it logs everyone out.
- Keep `DEBUG=false` in production (set by `render.yaml`).
